# RevenueOS — Return on Investment (ROI) & Financial Quantification Model

## 1. Executive Summary

RevenueOS enforces a **Strict Financial Truth Standard**:
* **Predicted / Expected Revenue is an Operational Prioritization Signal, NEVER a Realized Gain.**
* **Only Provider-Reconciled, Cryptographically-Verified Settlements Count Toward Actual Recovered Revenue.**
* **Double Counting is Mathematically Prohibited Across All Funnels and Ledgers.**

This document details the deterministic mathematical framework used by RevenueOS to quantify Revenue at Risk (RAR), Expected Recovery Value, System Operating Cost, Net Recovered Revenue, and the Transparent ROI Multiplier.

---

## 2. Core Financial Definitions

| Metric | Symbol | Definition | Source of Truth |
| :--- | :--- | :--- | :--- |
| **Gross Revenue at Risk** | $RAR_{gross}$ | Total monetary value of failed transactions and abandoned carts. | Failed payments (`amount`) + open leaks (`revenue_at_risk`) |
| **Potentially Recoverable Value** | $V_{pot}$ | Monetary value of transactions eligible for automated recovery. | $V_{pot} \le RAR_{gross}$, excludes hard fraud, closed accounts |
| **Recovery Probability** | $P_{rec}$ | Calibrated ML probability of successful payment settlement. | LightGBM inference model ($0.00 \le P_{rec} \le 1.00$) |
| **Expected Recovery Value** | $EV$ | Risk-weighted value used for priority sorting. | $EV = V_{pot} \times P_{rec}$ |
| **System Cost** | $C_{sys}$ | Cost incurred by platform messaging, cloud compute, and provider APIs. | $C_{sys} = (N_{verified} \times ₹15.00) + ₹150.00$ base |
| **Actual Recovered Revenue** | $R_{act}$ | Cash actually settled into the merchant's gateway account. | Sum of verified `RecoveryAction.actual_recovered_amount` |
| **Net Financial Gain** | $G_{net}$ | Net profit generated for the merchant after all costs. | $G_{net} = \max(₹0.00, R_{act} - C_{sys})$ |
| **ROI Multiplier** | $ROI$ | Return on capital investment ratio. | $ROI = \frac{G_{net}}{C_{sys}}$ |

## 3. Mathematical Formulas

### 3.1 Gross Revenue at Risk ($RAR_{gross}$)
$$RAR_{gross} = \sum_{p \in \text{Failed Payments}} p.\text{amount} + \sum_{l \in \text{Open Leaks}} l.\text{revenue\_at\_risk}$$

### 3.2 Expected Recovery Value ($EV$)
For any recovery opportunity $i$:
$$EV_i = \text{quantize\_inr}(V_{pot, i} \times P_{rec, i})$$
Where:
- $V_{pot, i}$ is the failed transaction amount minus non-recoverable penalties.
- $P_{rec, i} \in [0, 1]$ is generated by the ensemble ML model utilizing customer historical payment tenure, hour of day, route latency, and error code transient score.

### 3.3 Strict Actual Recovered Revenue ($R_{act}$)
$$R_{act} = \sum_{a \in \mathcal{A}_{verified}} a.\text{actual\_recovered\_amount}$$
Where $\mathcal{A}_{verified}$ satisfies:
1. $a.\text{status} \in \{\text{'SUCCESS'}, \text{'VERIFIED'}\}$
2. $a.\text{verified\_status} \in \{\text{'confirmed'}, \text{'VERIFIED\_RECOVERED'}\}$
3. Razorpay webhook received with valid HMAC-SHA256 signature matching secret.
4. Reconciled with gateway provider record where $a.\text{actual\_recovered\_amount} = \text{settled\_amount}$.

> [!IMPORTANT]
> If a provider webhook reports a partial settlement (e.g. ₹3,000 received for an expected ₹5,000 action), the transaction is flagged with `RECONCILIATION_REQUIRED` and is **EXCLUDED** from $R_{act}$ until manual operator resolution.

### 3.4 Platform Operating Cost ($C_{sys}$)
To ensure radical transparency, RevenueOS attributes all marginal costs incurred in recovery:
$$C_{sys} = N_{verified} \times ₹15.00 + ₹150.00$$
Where:
- $₹15.00$ accounts for multi-channel SMS/WhatsApp notification delivery, Razorpay payment link API fees, and compute/database overhead per action.
- $₹150.00$ represents fixed platform infrastructure amortization per merchant billing cycle.

### 3.5 Net Financial Gain ($G_{net}$) & Transparent ROI
$$G_{net} = \max(0.00, R_{act} - C_{sys})$$
$$ROI_{\text{multiplier}} = \begin{cases} \frac{G_{net}}{C_{sys}} & \text{if } C_{sys} > 0 \text{ and } G_{net} > 0 \\ 0.0 & \text{otherwise} \end{cases}$$
$$ROI_{\%} = ROI_{\text{multiplier}} \times 100\%$$
